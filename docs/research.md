# Overall Architecture of the NFlow System

NFlow is a modern web-based **intelligent document processing and knowledge management system**. The application is built with a front-end interface using Next.js and React, while the modular back-end architecture allows for the separation of document processing, embedding creation, and data storage components ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=NFlow%20is%20built%20as%20a,processing%20and%20knowledge%20management%20capabilities)) ([GitHub - N2FlowJS/nflow: NFlow is an intelligent document processing and knowledge management system that leverages vector embeddings and natural language processing to extract, organize, and query information from various document formats.](https://github.com/N2FlowJS/nflow#:~:text=NFlow%20is%20an%20intelligent%20document,information%20from%20various%20document%20formats)). The system uses AI techniques such as vector embeddings and natural language processing (NLP) to extract, organize, and query information from various document formats (PDF, DOCX, XLSX, TXT, MD) ([GitHub - N2FlowJS/nflow: NFlow is an intelligent document processing and knowledge management system that leverages vector embeddings and natural language processing to extract, organize, and query information from various document formats.](https://github.com/N2FlowJS/nflow#:~:text=NFlow%20is%20an%20intelligent%20document,information%20from%20various%20document%20formats)). The main components and technologies used include:

- **User Interface (Frontend Layer):** The application uses **Next.js** (React) to build the interface for the browser. The interface includes **React components** and applies the **Ant Design** UI library to display UI elements. Additionally, **Tailwind CSS** is used for the utility-first styling system and **XYFlow** for visualizing process diagrams on the interface ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=1)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Frontend)). Client-side state is managed to provide a smooth interactive experience.

- **API/Backend Layer (API Layer):** The back-end platform is also implemented as **Next.js API Routes** (serverless functions), allowing the construction of **RESTful APIs** to serve requests from the interface or external integrations ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=%2A%20Client,API%20Layer)). This layer handles authentication (JWT via NextAuth), authorization (RBAC), and executes business functions. The main endpoints include user/auth management (`/api/auth`, `/api/user`), document management (`/api/files`), knowledge base management (`/api/knowledge`), and AI processing APIs such as `/api/llm`, `/api/agent` for generating automatic responses. The back-end code is written in **TypeScript**, runs on **Node.js**, and uses **Prisma ORM** to connect to the relational database ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Vector%20database%20for%20similarity%20search)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,File%20storage%20for%20document%20management)).

- **Document Processing and Embedding Layer (Processing Layer):** This is the main business processing part of the system. NFlow provides specialized **services** such as *Document Service*, *Embedding Service*, *Vector Database Service*, *Knowledge Service*, etc. These services are responsible for:
  - **Document Analysis:** Using third-party libraries (such as `pdf2json`, `officeparser`, `mammoth`...) to **extract text and metadata** from various file formats. The extracted text will be **split into chunks** for easy further processing ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Storage%20Layer)).
  - **Embedding Creation:** Calling the **OpenAI API** to create embedding vectors for each text chunk. This is the step of converting from natural language to vector space to serve semantic search ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Storage%20Layer)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Backend)).
  - **Vector Storage and Query:** The obtained vectors will be stored in a vector database. NFlow supports two main options: storing directly in **SQLite (local)** or using **NBase** – a dedicated vector database included with the system, optimized for high-performance approximate search ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,File%20storage%20for%20document%20management)) ([nflow/docs/vector-database.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/vector-database.md#:~:text=NFlow%20supports%20two%20primary%20vector,database%20options)). Processing services manage adding, searching, and deleting vectors through the NBase API or performing brute-force search on the vector set stored in SQLite.
  - **Knowledge Management:** Building a knowledge graph from structured data extracted (through *Knowledge Service*). Users can create, update, and query stored knowledge (entities, relationships) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=The%20core%20data%20model%20includes,the%20following%20entities)).

- **Storage Layer:** NFlow uses **Prisma ORM** to interact with the relational database. The default is **SQLite** (file-based) but also supports **PostgreSQL** for large-scale production ([GitHub - N2FlowJS/nflow: NFlow is an intelligent document processing and knowledge management system that leverages vector embeddings and natural language processing to extract, organize, and query information from various document formats.](https://github.com/N2FlowJS/nflow#:~:text=Variable%20Description%20Default%20,http%3A%2F%2Flocalhost%3A3000)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Database)). The main tables include *User* (user), *File* (file metadata), *TextChunk* (extracted text segment) – where *TextChunk* contains embeddings if using local vector storage ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=The%20core%20data%20model%20includes,the%20following%20entities)). In addition, the system stores document files (original files) on the hard drive or optional storage service. With NBase, vectors are stored in a separate structure, indexed for fast search. With SQLite, vectors are stored as JSON in the corresponding column of the table and searched using cosine comparison on RAM (suitable for small datasets) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,File%20storage%20for%20document%20management)) ([nflow/docs/vector-database.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/vector-database.md#:~:text=1,used%20as%20the%20distance%20metric)).

- **Integration and Utility Layer (Integration Layer):** NFlow supports integration with other systems via REST APIs and **webhooks** (sending event notifications). The system also has **export/import** functionality for knowledge exchange. In addition, NFlow allows setting up **automatic workflows** (Automation) – when an event is triggered, the system automatically runs document processing steps and saves the results, then notifies the user ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=5)).

## Technologies Used by Layer

- **Frontend:** Next.js (React) combined with the **Ant Design** component library for the interface. Using **React 19**, **Tailwind CSS**, and the **XYFlow** plugin to draw flow diagrams on the interface ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Frontend)).

- **Backend/API:** Running on **Node.js**, source code written in **TypeScript**. Using **Next.js API Routes** to route backend functions as serverless functions ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=%2A%20Client,API%20Layer)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Vector%20database%20for%20similarity%20search)). **Prisma ORM** manages the data model and database migrations ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Vector%20database%20for%20similarity%20search)). Integrates **OpenAI SDK** to call APIs for creating embeddings (and can generate answers with LLM when needed). If using NBase, the backend communicates with the NBase server via REST to store/query vectors.

- **Database:** Default **SQLite** (lightweight, easy to initialize) but can configure **PostgreSQL** for production environments ([GitHub - N2FlowJS/nflow: NFlow is an intelligent document processing and knowledge management system that leverages vector embeddings and natural language processing to extract, organize, and query information from various document formats.](https://github.com/N2FlowJS/nflow#:~:text=Variable%20Description%20Default%20,http%3A%2F%2Flocalhost%3A3000)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Database)). With SQLite, vectors are stored internally; with NBase, vectors are stored on a dedicated NBase server. Prisma is used to interact with the relational database (the tables mentioned above) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,File%20storage%20for%20document%20management)).

- **Other:** Supporting libraries include **multer/formidable** for receiving file uploads, **bcryptjs** and **jsonwebtoken** for JWT authentication, **framer-motion**, **react-markdown**, **react-mentions** for UI interactions (marking and mentioning in text), and **xlsx** for reading spreadsheet files, **mammoth/pdf2json/officeparser** for converting documents to text ([nflow/package.json at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/package.json#:~:text=)).

## Document Processing and Query Flow

The entire process of NFlow consists of two main stages: *document ingestion* and *knowledge query*.

- **Document Ingestion:** The user uploads a document through the web interface, which is sent to an API endpoint (e.g., `/api/files/upload`). The system saves the original file to storage, then the **Document Service** will process the file: extract text and metadata. The obtained text is divided into small segments (e.g., by sentence or paragraph) to increase search efficiency. Each text segment will be used by the **Embedding Service** to use the OpenAI API to create a vector embedding. These vectors are stored using **VectorDB Service**: if using SQLite, they are stored with the `TextChunk` table; if using NBase, the NBase API is called to store and index. In addition, the text content and structured information are also stored in the relational database (via Prisma) under the corresponding tables. These data transfer steps are summarized as follows:

  > *Upload → Parse (extract) → Chunk (segment) → Create embedding → Save vector and text* ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=1)).

- **Knowledge Query:** When a user submits a query (which can be a question or keyword), the system processes the input information similarly: the query string is converted into an embedding (calling OpenAI). Then, the **VectorDB Service** performs a search for vectors in the vector database that are most similar to the query embedding. The system returns the most relevant text segments. These results are fed into the **Knowledge Service** or an LLM-based answer generator to synthesize an answer. The entire process can be described as:

  > *Query text → Create embedding → Search vector → Collect results → Format answer* ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=2)).

Thus, NFlow tightly integrates the frontend, API, document processing, and storage layers. The frontend communicates via API with the backend, the backend coordinates processing services and interacts with the database (relational and vector). This architecture supports both stream processing (synchronous) and event-driven automation (workflows), allowing flexible expansion and integration with other systems ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=5)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=Security%20Architecture)).

**In summary**, NFlow uses Next.js/React for the interface, Next.js API + Node.js for the backend, Prisma + SQLite/Postgre for relational data, and integrates the NBase system or stores vectors internally to perform semantic search using embeddings ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Vector%20database%20for%20similarity%20search)) ([nflow/docs/vector-database.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/vector-database.md#:~:text=NFlow%20supports%20two%20primary%20vector,database%20options)). The processing flow starts from uploading the document, through the steps of extracting and embedding vectors, until the user queries and receives information from the system of related data segments ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=1)) ([nflow/docs/technical-architecture.md at main · N2FlowJS/nflow · GitHub](https://github.com/N2FlowJS/nflow/blob/main/docs/technical-architecture.md#:~:text=,Storage%20Layer)).
